# AI 自動描画・作業 Agent の開発計画

更新日: 2026-09-05。3本柱を実装済み。実モデルでの生成と参考画質への到達は未検証。

## 目標

AI が ai-paint の全機能を使い、工程に沿って描画・確認・修正を繰り返し、利用者が用意した参考画像の水準の絵を完成させる。制作過程も保存・再生できるようにする。参考画像は、利用する権利を持つものを各自で用意する。

開発の柱は、**GPT 対応 → 全機能の API 化 → 作業 Agent の実装**の3つ。

## 1. モデルの拡張：GPT に対応する

- 現在の Claude 対応に GPT を追加し、モデルを選択できるようにする。
- テキスト・キャンバス画像の送信と、アプリ機能の呼び出しに対応する。
- モデルごとの通信処理を分け、作業 Agent は共通の呼び出し方で利用する。

Tauri 側から OpenAI Responses API / Anthropic Messages API に接続し、[Function calling](https://developers.openai.com/api/docs/guides/function-calling) で操作する。初期モデルは [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)（`gpt-6-astra`） / `claude-sonnet-4-5`。モデル名は変更できる。既存の解析・チャットは Claude のまま維持する。

**完了条件:** GPT がキャンバスを見て、アプリに操作を要求し、その実行結果を受け取れる。

## 2. 機能の API 化：全機能を取得・操作できるようにする

API は、Agent が ai-paint の機能を呼び出すための共通の窓口とする。

- **取得:** キャンバス全体・部分画像、レイヤー、選択範囲、ツール設定、履歴、作業状態など。
- **操作:** 描画、消去、塗りつぶし、図形、変形、色調補正、レイヤー編集、Undo/Redo、タブ、設定、保存・読込・書き出し、バックアップ、既存の AI 機能など。
- **機能の発見:** 利用可能な API の一覧、引数、返り値、使い方を取得できるようにする。
- 全機能と API の対応表を作り、UI からできることに API の抜けがないか確認する。
- UI 操作と API 操作は同じ処理を使い、履歴・変更状態・保存結果も一致させる。

**完了条件:** 全機能を API 経由で取得・操作でき、実行結果やエラーを Agent に返せる。

## 3. 作業 Agent：工程に沿って反復する

Agent が制作計画と現在の工程を持ち、API を使って作業を進める。

工程例: **構図 → ラフ → 線画 → ベース塗り → 影 → ハイライト → 仕上げ**

各工程では、次のループを繰り返す。

1. 現在の絵と作業状態を取得する。
2. 工程の目的に対して不足している点を判断する。
3. 必要な API を呼び出して描く・直す。
4. 結果を画像で確認する。
5. 不十分なら修正を繰り返し、工程の完了条件を満たしたら次へ進む。

工程、完了条件、現在位置、修正事項を保持する。必要なら前の工程へ戻る。一時停止・再開・中止と、回数・時間・使用量の上限を設ける。

実際に行った操作と工程を記録し、制作過程の再生に使う。保存・再読込後も記録を再生し、途中から作業を続けられるようにする。

**完了条件:** 指示から制作を始め、描画結果を見ながら修正し、工程を進めて完成まで作業できる。制作過程を保存・再生できる。

## 進め方

1. **GPT 接続と共通のモデル呼び出しを実装する。**
2. **全機能を棚卸しし、API として公開する。** 描画・画像取得から接続し、全機能へ広げる。
3. **作業 Agent を実装する。** まず「描く → 見る → 直す」を通し、工程管理・停止再開・記録再生を加える。
4. **参考水準の絵で確認する。** 完成絵の品質、工程に沿った反復、保存後の再生・作業再開を実物で検証する。

描画・編集・保存・設定・既存AIなどのAPIと、工程ごとの反復・停止再開・制作記録を接続した。[対応表と仕様](./paint-api.md)を参照。

## 右パネル・画質・進捗・お手本の改善

- ダイアログを廃止し、右パネルへ移動。制作・記録再生は既存キャンバスを使う。
- お手本を最大3枚添付し、モデルへ目標画像として渡す。制作記録に保存し、再開でも使う。
- 対応GPTモデルにhigh reasoningを指定し、全体の形・配色・レイヤー分離・部分確認から細部へ進む指示にする。工程ごとに実画像の変化と描画後の確認を必須にする。
- 作業内容、応答待ち時間、最終進捗からの時間、工程数、停止理由を常時表示。入力・出力・合計トークンと各回数上限を画面から調整できる。

これらは制作を改善する仕組みであり、参考画像の水準への到達は実生成で別途確認する。
