# 見本からブラシ再描画する試作

## 目的と範囲

完成見本を座標・色・筆圧の操作列に変換し、既存のブラシエンジンと実キャンバスで再構成できるかを検証する。GPTや画像生成APIは呼ばない。2026-09-05に通常パネルのAIドロー（β版）へ統合した。人物の部位を理解した描画順序は次段階。

通常アプリでは「AIドロー（β版）」→「描画方法: お手本を再描画」→画像添付→「再描画を開始」。現在のキャンバスに独立したフォルダと工程レイヤーを追加し、進捗表示・中止・制作過程の再生・`.aipaint`への記録保存を行う。[APIと保存仕様](./paint-api.md)を参照。以下は独立した検証ページの使用方法・測定結果。

開発サーバーで `/experiments/reference-paint.html` を開き、完成見本を選んで「再描画を試す」を押す。既存アプリを左、試作の操作を右に置く。実キャンバスの新規タブへ描画し、ユーザーの元の絵は上書きしない。実験ページは製品ビルドのエントリには含めていない。

## 描画と保存

- Worker内で輪郭抽出、太い筆から細い筆への描画、完成見本との差の修正を行う。推定面にも既存の丸ブラシエンジンを使う。
- 元画像を含まない `ReferencePaintPlan` に、白背景、工程ごとの全筆致、推定した色差を保持する。
- 実キャンバスの最下層を白で塗り、工程ごとにレイヤーを追加する。`drawing.stroke_batch` で1,024筆・合計32,768点以下に分割し、描画順を保つ。
- 1バッチがUndoの1操作になる。小さいバッチで全画面の履歴を大量に保存するのを避ける。履歴容量を超えた際の古いUndoの破棄は、通常アプリと同じ共有上限に従う。
- 進捗は解析工程・筆数と実行済み筆数を表示。中止は解析Workerを終了し、描画中なら現在のバッチ終了後に停止する。途中のタブは残り、アプリ側から手動保存できる。
- 再生は実キャンバスから取得したバッチ完了時のフレーム。全ての筆致をリアルタイムで再実行するプレイヤーは未実装だが、JSONから再実行して完成画素が一致することをE2Eで検証する。

「検証結果を保存」のZIPには比較・再生できる `replay.html`、`reference.png`、`painted.png`、`painted.aipaint`、`strokes.json`、`metrics.json`、6工程のPNGを含む。`.aipaint` は編集用の白背景と工程レイヤーを保存する。試作の再生記録は別のHTML/JSONに保存し、通常Agentの制作記録とは混同しない。保存対象は実行完了時に固定し、その後のタブ切り替えに影響されない。

入力は20MB以下、最大辺768pxかつ30万画素へ縮小する。操作数は最大6万筆。超えそうな場合は解析の細かさを自動調整し、全工程を作り直す。描画範囲と配置は維持するが、細かな模様は粗くなる場合がある。調整中も進捗を表示し、中止できる。高解像度全般の品質・速度は未検証。

## 2026-09-05の検証結果

ユーザーが添付した完成画面から、動画の操作バーを除いた絵部分282×318pxを切り出した。元の高解像度イラストではない。

| 項目 | 結果 |
| --- | --- |
| 筆数 | 35,626 |
| ブラシAPI呼び出し | 37回（別途白背景の塗りつぶし1回） |
| 解析 | 0.94秒 |
| 実キャンバスでの描画・撮影 | 2.55秒 |
| 最も長いブラシバッチ | 49.5ms |
| 実画像の平均RGB絶対誤差 | 2.70 / 255 |
| Worker推定の平均RGB絶対誤差 | 2.70 / 255 |
| ピクセル履歴の上限見積もり | 約26MiB（全バッチが全画面を保存するとして、白背景を含む38操作） |

速度はローカルChromiumでの1回の測定。RGB誤差は画素の近さであり、美術的な品質や工程の自然さの評価ではない。

輪郭・配色・細部をかなり保って再構成できた。一方、下描きは色の境界線なので二重線や途切れがあり、最初の色塗りは画面全体の粗い筆跡になる。お手本の「髪、肌、服、陰影、細部」の順序はまだ表現していない。次は部位のマスクと描画順を与え、色面が線画を崩さず、部位ごとに完成していく処理を検証する。

## 再実行とテスト

通常はファイル選択で任意の見本を渡す。今回と同じ添付画像を使う場合だけ、元のスクリーンショットを追跡対象外の `ui-snapshots/reference-paint/input.png` に置き、`/experiments/reference-paint.html?sample=miku&auto=1` を開く。切り出し座標はこの画像専用。

```powershell
npm run lint
npm run build
npm run test:unit
npm run test:e2e -- tests/e2e/reference-paint.spec.ts tests/e2e/reference-paint-integration.spec.ts tests/e2e/paint-api.spec.ts tests/e2e/drawing-agent-integration.spec.ts
```

添付画像の実行・成果物の保存も検証する場合は、ファイル配置後に次を実行する。

```powershell
$env:AI_PAINT_REFERENCE_CAPTURE = '1'
npm run test:e2e -- tests/e2e/reference-paint.spec.ts --grep 'optional local reference'
Remove-Item Env:AI_PAINT_REFERENCE_CAPTURE
```

成果物は `ui-snapshots/reference-paint/result/` に保存する。通常テストは添付画像に依存せず、合成した色面・細線の見本で画質改善、JSON再描画、プロジェクトの再読込後のPNG一致、タブ切り替え後の保存対象、Worker中止と再実行を確認する。
